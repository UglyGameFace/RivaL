# Automatic shadow evaluation (no trading)

After Discloud deploys a passing commit, RivaL's existing PostgreSQL
perpetual collector continues to run as before. A separate, low-priority
background task now reevaluates locally stored market history once per hour
(`RIVAL_SHADOW_EVAL_SECONDS`, allowed 900–21600). Set
`RIVAL_SHADOW_LEARNING_ENABLED=false` to disable shadow work while leaving
live market collection and Discord functioning.

- No exchange requests, Gemini requests, account credentials, leverage,
  trade execution or Discord messages are generated by this worker.
- At most ten distinct, recently collecting market streams per cycle; least
  recently evaluated streams are served first across bot restarts.
- The worker queries at most 1,000 *already stored* 5-minute candles per
  stream and processes 5-minute and 15-minute prediction horizons. Only
  source observations first recorded before the as-of time are visible.
- Training is online-in-sequence and strictly uses resolved prior outcomes.
  Backfilled data discovered at once cannot qualify as genuine forward
  evaluation evidence. Source data with invalid timing is skipped.
- The independent PostgreSQL table `perp_shadow_evaluations` stores sample
  counts, settled evaluations, proper Brier scores, a base-rate baseline and
  whether a *shadow candidate* beat its baseline. Updates are idempotent per
  venue/contract/quote/horizon/model version. No model checkpoints are
  promoted or used for live long/short calls.
- `/rival-research` -> **Math & History** displays aggregated,
  settled-outcome metrics only after 50 evaluated outcomes per stream.
  Metrics from overlapping venues and horizons must not be treated as
  independent market accuracy. The menu explicitly distinguishes shadow
  evidence from validated deployable signals.
- If a cycle fails, it logs a sanitized failure and tries again later.
  Discord and the market collector keep running. The worker is cancelled
  and joined on shutdown, before PostgreSQL closes.

This is *automatic recurring shadow retraining/evaluation*, not the
production self-learning forecasting system requested in issue #6.
Still required: backfill/quality audits, reliable reconciliation of actual
outcomes, independent holdout/calibration, versioned approved model registry,
multi-venue prediction generation and real-world performance checks.
A successful Github Actions run does not prove that Discloud actually ran
the worker; inspect deployed logs (`RivaL automatic shadow learning`) and
the research panel for production evidence.
