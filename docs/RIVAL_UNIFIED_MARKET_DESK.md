# One Live Market Desk, One Verified Market Source

- The existing `/rival → Live Mode` now opens one compact **Live Markets** screen. Provider buttons on that screen select **Polymarket Global** (Gamma/CLOB, 5m/15m), **Kalshi** (source-specific open crypto contracts), or **DraftKings Predictions** (marked unavailable until verified official market-data and contract rules are integrated). No new slash commands, consumer notification workers, or duplicate Kalshi submenu are necessary. The legacy `kalshi` action resolves back into the unified screen.
- For Polymarket, the default screen displays its actual verified current event, price-to-beat only if in source metadata, current UP/DOWN ask quotes with observed age, and its next listed event. It separately displays the exchange-candle model's fresh, time-aligned UP/DOWN research lean **without ever treating a CLOB share price as a probability or approving a bet**. Missing or expired data show WAIT/unavailable.
- Start Auto-Track continues to edit one private Discord message approximately every 15s, without repeatedly pressing Refresh. The menu uses a short bounded source-specific preview and cached verified tracker observations; it does not continuously edit already-sent Discord ephemeral menus. Existing opt-in alerts and historical records remain, but advanced alert choices are a single **Alert Settings** button rather than the focus of the live screen.
- Kalshi uses its already-existing on-demand public reader, no background per-coin worker, and respects each event's actual individual title, close, YES/NO asks and settlement wording; it does not offer fake Polymarket-style 5m or 15m labels. DraftKings Predictions is not a sportsbook feed.
- Polymarket `display_only=True` previously bypassed all market caches, fetching CLOB/Gamma repeatedly when both the live board and Auto-Hunt scanned a market. Short 5s per-slug display cache + slug-keyed concurrent Gamma listing lock coalesce this traffic; positive fresh display notices may be reused for ordinary alerts **only if** they also meet the stricter 90s remaining-time gate. A negative/expired display result cannot satisfy that gate.
- Source data delivery latency is still measurable in the bot logs. HTTP 200 does not prove a Gamma listing passed time, identity, token or oracle validation. The prior 44-second alert issue-to-delivery time and intermittent market validation failures require production timing/trace checks after this merge.
- This change does not train or promote a Polymarket-specific model, and it does not establish an after-cost profitable edge. The live contract decision stays WAIT unless independent calibrated, source-matched, prospective outcomes satisfy the promotion gates. More buttons do not create reliable predictions.
